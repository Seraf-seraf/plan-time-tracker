# Планы, статусы этапов и время работы

Сохраняйте исходный текст плана, его этапы и оценки в подключённом «Трекере планов». Время работы считает сервер. Для работы нужны доступные MCP-инструменты и аутентифицированный владелец. Берите текущие имена инструментов из discovery. Доступные функции проверяйте через GetTrackerInfo.

## Сохранить план

1. Составьте полный план в Markdown, включая контекст, действия, критерии приёмки и необходимые проверки. Передавайте весь исходный текст в CreatePlan.payload.planText без пересказа в отдельных технических полях.
2. Оформляйте этапы заголовками одного уровня: `## Этап 1. Название`, `## Этап DATA-001. Название` или `## G1. Название`. Заголовки этапов внутри блоков кода не создают этапов. Поддерживаются до 60 000 символов и 100 этапов; идентификаторы заголовков должны быть уникальными.
3. Вызовите CreatePlan с `schemaVersion:1`, UUID `commandId`, `payload:{title,planText,planCreatedAt}`. `planCreatedAt` задаёт исходную дату составления с точностью dateOnly или instant и часовым поясом. Источник беседы или задачи можно указать через sourceReference.
4. Сохраните возвращённый planId, прочитайте GetPlanProgress и сохраните stepId, текущий статус и version каждого этапа. После создания план остаётся PLANNED, таймер не запускается.

Храните один контекст на planId. Не создавайте дубликат плана после потерянного ответа или передачи задачи другому исполнителю. Перед продолжением найдите и прочитайте существующий план. ListPlans использует стабильную пагинацию nextCursor; при поиске прочитайте все нужные страницы.

Исходный Markdown сохраняется неизменным. UpdatePlan редактирует метаданные, название и дату; эта команда не переписывает исходный документ. Критерии выполнения и команды проверок находятся в тексте плана.

## Оценить задачу до первого запуска плана

Применяйте соседний assess-task. Через GetTrackerInfo найдите `assessments.atlm`, прочитайте GetTaskAssessment без assessmentId и сохраните currentRequirementsDigest до анализа задачи. SaveTaskAssessment передаёт исходные факты `context.agentTask` и `predictionRequest:{method:"ATLM",methodVersion:1}`. Сервер возвращает `serverEstimation`; агент не задаёт веса, коэффициенты или длительности примеров. Гибрид agent-v3-hybrid сравнивает OLS и ridge по более ранним результатам; фактически использованный решатель находится в serverEstimation.hybrid.usedEngine. historical-median — отдельный ориентир, проверяйте method и не называйте медиану обученной ATLM. Выбор ветви, lambda и исходные значения агент не подгоняет.

Прогноз показывает полное активное время плана PLAN_ACTIVE от первого StartPlan. UNKNOWN/null и отсутствие модели не мешают выполнять разрешённую работу. Для текущего read-only пересчёта PLANNED по последним сохранённым признакам и текущей истории используйте GetSavedEstimate; recordedEstimation — исходная сохранённая оценка, после первого запуска возвращается frozen-снимок; GetTrainingStatus показывает состояние данных и модели. ContinueTraining продолжает ограниченную серверную обработку, StartTraining вызывается только по просьбе пользователя запустить обучение. Исходный снимок после первого запуска не заменяется поздними оценками.

## Выполнить работу и обновить статус этапа

Выполняйте работу в пределах поручения пользователя. Просьба выполнить или продолжить задачу разрешает соответствующий StartPlan или ResumePlan. Просьба только составить план оставляет его PLANNED. Не запрашивайте то же разрешение повторно.

Для изменения этапа вызовите SetStepStatus:

```json
{
  "schemaVersion": 1,
  "commandId": "<новый UUID>",
  "expectedVersion": 1,
  "payload": {"stepId": "<UUID этапа>", "status": "RUNNING"}
}
```

Используйте текущую version этапа из GetPlanProgress. Изменение разрешено для RUNNING-плана, который не удалён. Версия этапа и версия плана независимы.

- PENDING — работа по этапу ещё не началась.
- RUNNING — этап выполняется.
- BLOCKED — работу нельзя продолжить; сообщите пользователю причину.
- FAILED — выполнить этап не удалось.
- DONE — фактический результат и необходимые проверки соответствуют критериям плана.

Проверки выполняйте в рабочей среде и сообщайте результат пользователю. Трекер хранит текущее состояние этапа; отдельные записи результатов, проверок, событий смены статуса и назначений исполнителю не создаются. После успешного SetStepStatus сохраните возвращённую version. Не записывайте DONE заранее и не называйте неподтверждённую запись успешной.

Статус этапа не запускает и не останавливает таймер плана. При `steps.timing.available=true` подтверждённый SetStepStatus со статусом RUNNING открывает интервал этапа, другой статус закрывает его. Повтор RUNNING не создаёт второй открытый интервал. Время этапа считается только внутри активных интервалов плана, без пауз; параллельные этапы учитываются независимо. После обновления прежнее время не восстанавливается из статусов или квитанций; для уже выполняемого этапа повторный RUNNING начинает измерение с текущего момента. StartPlan, PausePlan, ResumePlan и FinishPlan работают с серверными интервалами конкретного planId. Несколько планов могут быть RUNNING одновременно; действие по одному не должно менять другой. Общее время владельца — объединение пересекающихся интервалов, сумма времени планов — отдельная величина.

PausePlan и FinishPlan требуют соответствующего намерения пользователя. Завершённый ответ, молчание, ночь, выходные или ожидание инструмента сами по себе не меняют интервалы. Для обычного FinishPlan все этапы должны быть DONE. Завершение с незавершёнными этапами требует явного решения и причины в `allowIncomplete:true, reason`.

## Повторить команду после потери ответа

Все записи используют стабильный UUID commandId и expectedVersion нужной сущности. При потере ответа сохраняйте точный конверт и повторяйте его с тем же commandId либо прочитайте GetCommandResult. Квитанция обеспечивает защиту от повторного применения команды и не служит журналом статусов.

При VERSION_CONFLICT перечитайте GetPlanProgress или GetPlan, сверьте текущую версию и намерение. После определённого отказа новая изменённая команда получает новый commandId. Никогда не подменяйте поля старого конверта, чей исход неизвестен. При ASSESSMENT_CONTEXT_CHANGED заново изучите требования и пересмотрите оценку, сохранив исходную ревизию.

При передаче работы сообщите planId, stepId, текущие версии и статусы, ссылку на исходный документ, assessmentId/revision и ожидаемый результат. При продолжении прочитайте сохранённое текущее состояние и выполните разрешённую задачу. Повторные назначения, продление прав исполнения и фоновые события активности не требуются.

## Удалить или восстановить план

DeletePlan и RestorePlan вызываются по просьбе пользователя для конкретного planId с текущей версией плана. Удаление закрывает его открытый интервал, переводит RUNNING-план в PAUSED и выполнявшиеся этапы в BLOCKED. Исходный текст, текущие состояния и измеренное время сохраняются. Остальные планы продолжают работу независимо.

RestorePlan восстанавливает план без запуска времени. ListPlans по умолчанию скрывает удалённые планы, `deleted:true` показывает только их. Удалённый план доступен для чтения по ID и не принимает изменения до восстановления. Не создавайте его копию и не восстанавливайте его автоматически. Аналитика исключает удалённые планы; восстановление возвращает сохранённые интервалы в отчёты.

## Аналитика и экспорт

GetTimeReport возвращает факты времени плана за календарный период в заданном часовом поясе: totalActiveMs, activeByDay, sumPlanActiveMs и показатели завершённых планов. GetTimeHistory читает оценки выбранных targets и факты PLAN_ACTIVE, CALENDAR и PAUSED, сохраняя asOf и границу пагинации оценок. Текущая готовность этапов не является историческим состоянием на asOf.

Для прогнозов используйте ATLM и исходные признаки assess-task. Текущие статусы не входят в девять исходных признаков. Сервер определяет обучающие примеры, критерии их пригодности, фактическое время и активную модель. Не выводите время этапов из последовательности статусов.

Экспорт версии 2 содержит исходный текст, текущие этапы, интервалы, оценки и причины явного завершения. Он не содержит журнал выполнения этапов. Не сохраняйте секреты, полные логи инструментов или исходники проекта в полях трекера.

# Проверки трекера

Из каталога приложения выполните `npm ci` и `npm test`. Тестам нужен Node.js с `node:sqlite`. `npm test` собирает Worker, затем проверяет сервер, миграции, изоляцию владельцев, повторы команд, конкуренцию, оценки и ATLM. `npm run validate` проверяет точку входа собранного Worker. Тест упаковки сверяет все SQL-файлы в сборке с `drizzle/`.

Для `npm run test:ui` предоставьте модуль Playwright и исполняемый файл Chromium. По умолчанию скрипты импортируют `playwright` и используют `/usr/bin/chromium`. Если зависимости лежат в другом месте, укажите `PLAYWRIGHT_MODULE` и `CHROMIUM_EXECUTABLE`. `UI_ACCEPTANCE_ARTIFACT_DIR` задаёт общий каталог снимков. Браузерные сценарии используют изолированную SQLite.

ATLM проверяется на известных численных примерах, пропусках, широких матрицах, хронологическом replay, интервалах, ограничениях ресурсов, восстановлении очереди и истории попыток. UI-тесты проверяют текущий и зафиксированный прогнозы, факт, ошибки и повтор, фильтр периода, пагинацию, клавиатуру и размеры экрана. `scripts/evaluate-atlm.mjs` читает полный журнал формата 3. Синтетические данные не доказывают точность на реальных задачах.

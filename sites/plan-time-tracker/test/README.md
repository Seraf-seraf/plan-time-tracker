# Проверки текущей модели

`npm test` проверяет календарное время, изоляцию владельцев, независимость планов, квитанции/CAS, исходный Markdown, текущие статусы, оценки, экспорт v2 и ATLM. `simple-model.test.js` проверяет физическое отсутствие удалённых таблиц, полей и API, точные повторы, конкурирующие записи и откат при сбое.

Миграционный сценарий загружает синтетический снимок прежней схемы из `fixtures/pre-simple-data.json`, включает foreign keys, применяет новую миграцию транзакционно и проверяет весь сохранённый рабочий набор. Снимок создан версией c05844c и содержит 15 обучающих примеров, активную модель и открытый интервал. Пользовательских записей в нём нет.

Для проверки фактического ledger Sites задайте `SITES_SOURCE_ROOT=/absolute/path/to/site/source` при запуске `node --test test/simple-model.test.js`. Старые SQL, metadata и snapshots не переписываются. `npm run validate` проверяет собранный Worker ESM и его default.fetch.

`npm run test:ui` запускает браузерные сценарии с реальным Worker и изолированной SQLite: чекбокс даты и клавиатура, статусная форма, исходный Markdown, точный повтор после потери ответа, параллельные планы, удаление/восстановление, пагинация, аналитика планов и ATLM. Все HTTP-запросы перехватываются; рабочий Site не используется. PLAYWRIGHT_MODULE и CHROMIUM_EXECUTABLE задают доступные зависимости, UI_ACCEPTANCE_ARTIFACT_DIR — каталог снимков.

Тесты старого механизма попыток, evidence snapshots и поэтапной атрибуции времени удалены вместе с механизмом. Новый сценарий миграции проверяет перенос этих данных и отсутствие путей исполнения удалённых команд.

`analytics-steps.test.js` проверяет новые явные интервалы этапов: паузы, параллельность, повтор статуса, точный повтор команды, rollback, завершение с исключением, удаление/восстановление, границы локальных дат и asOf, различие null/0, изоляцию и миграцию заполненной схемы 0021 без выдуманных измерений. `ui-analytics.mjs` проверяет отложенную загрузку, ошибку и повтор, обновление отчёта и поздний ответ, точные значения, длинные названия, 40 этапов и 320–1440 px. `ui-atlm.mjs` дополнительно проверяет реальный ручной запуск при недостатке данных, клавиатуру, защиту от двойной отправки и отсутствие автоматического повтора потерянного ответа.

## Гибрид ATLM

`atlm-core.test.js` и `atlm-runtime.test.js` сохраняют прежние эталоны именованного OLS agent-v2. `atlm-hybrid-core.test.js` проверяет ridge, широкие/зависимые матрицы и неизменность входов. `atlm-hybrid-evaluation.test.js` проверяет собственные сравнения, равенства в пределах 1 ms от общего минимума, наблюдавшиеся версии до cutoff, всю вложенную политику и CLI обоих форматов.

`atlm-training.test.js` проверяет возобновляемые BASE_CASE checkpoints, соответствие SQL as-of чистому воспроизведению журнала, подтверждённый выбор OLS на существующей численной фикстуре и совместимость чтения/CAS записи agent-v2. Поздняя загрузка фактов не создаёт фиктивных прошлых проверок; одинаковая ошибка предпочитает медиану и сохраняет прежний пригодный incumbent. `atlm-mcp.test.js` включает аудит реально сохранённой медианы в локальной обвязке; факт остаётся серверным интервалом.

`ui-atlm.mjs` проверяет фактически использованный OLS/ridge/медиану, FULL_POLICY ошибки и покрытие, раскрываемую диагностику, legacy-ответы, ошибки/гонки, клавиатуру и 320–1440 px. После сборки повторите `SITE_WORKER_MODULE="$PWD/dist/server/index.js" node test/ui-atlm.mjs`. PLAYWRIGHT_MODULE указывает при необходимости абсолютный index.mjs; CHROMIUM_EXECUTABLE — браузер.

Полезность проверяется отдельно на копии реальной истории через `node scripts/evaluate-atlm.mjs "$ATLM_HYBRID_DATASET"`. Для протокола 2 нужен formatVersion=2 с полным журналом OWNER_EXPORT одного datasetRevision/asOf. Файл и результаты находятся вне Git. Синтетические фикстуры не доказывают точность на владельческой истории; нельзя создавать рабочие обучающие планы для достижения нужной ошибки.

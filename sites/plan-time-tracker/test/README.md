# Проверки трекера

Из каталога приложения выполните `npm ci` и `npm test`. Тестам нужен Node.js 24 с `node:sqlite`. `npm test` собирает Worker, затем проверяет сервер, миграции, изоляцию владельцев, повторы команд, конкуренцию, оценки и ATLM. `npm run validate` проверяет точку входа собранного Worker. Тест упаковки сверяет все SQL-файлы в сборке с `drizzle/`.

Для `npm run test:ui` предоставьте модуль Playwright и исполняемый файл Chromium. По умолчанию скрипты импортируют `playwright` и используют `/usr/bin/chromium`. Если зависимости лежат в другом месте, укажите `PLAYWRIGHT_MODULE` и `CHROMIUM_EXECUTABLE`. `UI_ACCEPTANCE_ARTIFACT_DIR` задаёт общий каталог снимков. Браузерные сценарии используют изолированную SQLite.

Численные тесты ATLM покрывают известные примеры, пропуски, широкие матрицы, хронологический replay, интервалы и ограничения ресурсов. `atlm-local-training.test.js` запускает реальный CLI на синтетическом наборе и сверяет групповой split, веса, отчёты и повторы. `atlm-revisions.test.js`, `atlm-revision-files.test.js` и `atlm-model-evidence.test.js` проверяют замороженные источники, куски файлов, условную активацию, иммутабельные ревизии и сравнимость выданных прогнозов.

После `npm run build` сценарий `node --test test/atlm-agent-flow.test.js` проводит через собранный Worker снимок, разметку, точный экспорт, локальный fit, регистрацию, явную активацию и откат. Он проверяет сохранённые прогнозы до и после переключения. `node --test ../../plugin/plan-time-tracker/test/*.test.mjs` сверяет инструкции, discovery и содержимое архива.

UI-тесты проверяют прогнозы, раздел «Модель прогноза», источники качества, фильтры, пагинацию, клавиатуру и размеры экрана. Локальные тесты используют синтетические данные. Они подтверждают контракты и правила расчёта. Точность на реальных задачах и работу опубликованного connector проверяют отдельно.

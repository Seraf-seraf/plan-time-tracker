# Трекер планов: Worker 0.6.0

Приложение использует Cloudflare Worker ESM, привязку D1 `DB` и аутентифицированного владельца.

## Контракт

CreatePlan сохраняет исходный Markdown в `planText` и выделяет этапы по заголовкам одного уровня. GetPlan возвращает документ и метаданные; GetPlanProgress — текущие этапы `{stepId, ordinal, title, content, status, version}`. Идентификаторы в HTTP-снимке используют существующее имя `step_id`.

SetStepStatus принимает стандартный конверт `schemaVersion:1`, стабильный `commandId`, текущую `expectedVersion` этапа и `payload:{stepId,status}`. Разрешены PENDING, RUNNING, BLOCKED, FAILED и DONE. План должен быть RUNNING и не удалён. Обновление этапа и квитанция атомарны. Точный повтор возвращает прежний результат, другой payload с тем же ID отклоняется.

Статусы хранятся только как текущее состояние. API назначений, попыток, событий, истории статусов и старых отдельных результатов/проверок отсутствуют. Изменять исходный документ через UpdatePlan нельзя. Метаданные и дата редактируются с контролем версии плана; исправление даты сохраняет причину.

Время задаётся серверными Start/Pause/Resume/Finish. Несколько планов могут одновременно работать. Обычное завершение требует DONE у всех этапов; `allowIncomplete:true` с причиной сохраняет явное исключение. DeletePlan закрывает интервал своего плана, переводит его RUNNING в PAUSED и текущие RUNNING-этапы в BLOCKED. RestorePlan не запускает время.

GetTimeReport и `/api/analytics` используют только фактические интервалы планов: объединение по владельцу и локальным дням, отдельную сумму планов и выборку завершённых измеренных планов для медианы. GetTimeHistory возвращает PLAN_ACTIVE, CALENDAR, PAUSED и ревизии оценок. Экспорт — [формат 2](../../docs/json-report.md).

Для графиков `SetStepStatus` с RUNNING открывает серверный интервал этапа, другой статус закрывает его. `/api/analytics/plans/:planId/steps` возвращает записанное время с исключением пауз плана. Параллельные этапы измеряются независимо; прежнее время не реконструируется. Миграция 0022 добавляет интервалы без изменения существующих записей. [Контракт времени этапов](../../docs/plan-documents.md#записанное-время-этапов).

## ATLM и требования

Девять исходных признаков `agent-task-v1` сохраняются, включая допустимые неизвестные modelId/reasoningEffort/plannedParallelAgents. Метод `agent-v3-hybrid` выбирает OLS или ridge по прошлым ошибкам с медианой как явным запасным ориентиром. Ridge использует фиксированную lambda=1 и не требует полного ранга; пригодность данных и фактическое активное время не подменяются прогнозами. [Контракт гибрида](../../docs/atlm.md). Требования представлены текущими `assessment_targets`; миграция копирует прежний JSON без изменения digest. Assessment revisions, frozen inputs, samples и model artifacts сохраняются. Служебная очередь обучения имеет собственную защиту параллельного исполнения.

Ручной запуск доступен кнопкой «Начать обучение» и через `StartTraining`, независимо от двух новых планов. HTTP `POST /api/tracker/estimation-model/start` принимает `{}` и использует тот же процесс. Проверки данных и активации модели сохраняются.

## Схема и проверки

Каноническая установка применяет все SQL 0001–0024. Миграция 0021 удаляет старое исполнение и пересоздаёт команды с прямым изменением состояния. Все foreign keys проверяются после переноса. Старые команды нельзя продолжать или воспроизводить; их квитанции удаляются.

```sh
npm run build
npm run validate
npm test
npm run test:ui
node --test ../../plugin/plan-time-tracker/test/*.test.mjs
```

`test/simple-model.test.js` проверяет атомарность, CAS, точные повторы, изоляцию владельцев и перенос заполненной базы. С `SITES_SOURCE_ROOT=/absolute/sites/checkout` тот же тест выполняется на фактическом ledger Sites. `test/fixtures/pre-simple-data.json` — синтетический снимок прежней версии c05844c с открытым интервалом и моделью на 15 примерах; он не содержит пользовательских данных.

## Упаковка для Sites

Архив публикации сохраняет пути относительно корня проекта: `.openai/hosting.json`, `dist/server/index.js`, `dist/.openai/hosting.json` и `dist/.openai/drizzle/*.sql`. Нельзя переносить миграции из `dist/.openai/drizzle` в корневую `.openai/drizzle`: Worker может развернуться без применения новой схемы. Проверять наличие новых таблиц после публикации, а не только статус deployment.

Sites повторно использует сохранённую версию для одного source commit. Исправление ранее сохранённого архива требует новой ревизии исходников; повторная публикация прежнего commit не заменяет его архив.

## Выполнить работу и обновить статус этапа

Выполняйте работу в пределах поручения пользователя. По поручению выполнить или продолжить задачу прочитайте `GetPlanProgress`. У выбранного плана должно быть `deletedAt:null`. В `PLANNED` вызовите `StartPlan`, в `PAUSED` вызовите `ResumePlan`, в `RUNNING` продолжайте работу с открытым интервалом. Просьба только составить план оставляет его PLANNED. Не запрашивайте то же разрешение повторно.

Для изменения этапа передайте в `SetStepStatus` запрос с текущей версией этапа.

```json
{
  "schemaVersion": 1,
  "commandId": "<новый UUID>",
  "expectedVersion": 1,
  "payload": {"stepId": "<UUID этапа>", "status": "RUNNING"}
}
```

Используйте текущую version этапа из GetPlanProgress. Изменение разрешено для RUNNING-плана, который не удалён. Версия этапа и версия плана независимы.

- PENDING — работа по этапу ещё не началась.
- RUNNING — этап выполняется.
- BLOCKED — продолжение этапа зависит от устранения препятствия. Сообщите пользователю, что произошло и что позволит продолжить.
- DONE — фактический результат и необходимые проверки соответствуют критериям плана.

Проверки выполняйте в рабочей среде и сообщайте результат пользователю. Трекер хранит текущее состояние этапа. Отдельные записи результатов, проверок, событий смены статуса и назначений исполнителю не создаются. После успешного SetStepStatus сохраните возвращённую version. Не записывайте DONE заранее и не называйте неподтверждённую запись успешной.

Статус этапа не запускает и не останавливает таймер плана. Подтверждённый SetStepStatus со статусом RUNNING открывает интервал этапа, другой статус закрывает его. Повтор RUNNING сохраняет открытый интервал. Если его ещё нет, измерение начинается с текущего момента. Учитывается пересечение с активными интервалами плана. Параллельные этапы измеряются независимо. StartPlan, PausePlan, ResumePlan и FinishPlan работают с серверными интервалами конкретного planId. Несколько планов могут быть RUNNING одновременно. Действия применяются к выбранному плану. Общее время владельца — объединение пересекающихся интервалов, сумма времени планов — отдельная величина.

Вызовите PausePlan по намерению пользователя. Если блокировка остановила весь план, примените отдельный порядок. [Пауза после BLOCKED](blocked-step.md)

Вызывайте FinishPlan по намерению пользователя. Для обычного завершения все этапы должны быть DONE. Завершение с незавершёнными этапами требует явного решения и причины в `allowIncomplete:true, reason`.

# Трекер планов 0.6.0

Приватный трекер сохраняет исходный Markdown плана, текущие статусы этапов, серверные интервалы работы и оценки времени ATLM.

Этап содержит идентификатор, порядок, название, текст, текущий статус и версию. SetStepStatus напрямую меняет текущее состояние RUNNING-плана. Доступны PENDING, RUNNING, BLOCKED, FAILED и DONE. Запись статуса не управляет таймером плана. Подтверждённый RUNNING открывает интервал этапа; другой статус закрывает его. Аналитика показывает записанное время этапов без пауз плана. Старые этапы без измерений показываются как «Нет данных».

StartPlan, PausePlan, ResumePlan и FinishPlan задают интервалы конкретного плана. Для обычного завершения все его этапы должны быть DONE. Явное завершение с незавершёнными этапами сохраняет причину. Параллельные планы независимы; аналитика общего времени объединяет пересекающиеся интервалы.

Модель попыток выполнения этапов, аренды исполнителя, история статусов и старые записи результатов/проверок удалены из API и хранилища. Квитанции команд обеспечивают идемпотентность и восстановление после потери ответа. Исходные планы, текущие статусы, интервалы, оценки и обучающие данные сохраняются.

Обучение ATLM можно запустить в любое время кнопкой «Начать обучение» в настройках или попросить агента вызвать `StartTraining`. Пять новых пригодных планов — порог автоматического запуска. Ручная попытка также проходит проверки достаточности данных и качества; неудачный кандидат не заменяет действующую модель.

## Исходники и проверки

- `sites/plan-time-tracker/worker/` — Worker и UI.
- `sites/plan-time-tracker/drizzle/` — канонические миграции 0001–0022.
- `plugin/plan-time-tracker/` — локальный пакет с инструкциями track-plan и assess-task.
- [Контракт плана и статусов](docs/plan-documents.md).
- [Оценки и требования](docs/assessments.md), [ATLM](docs/atlm.md), [экспорт v2](docs/json-report.md).

```sh
cd sites/plan-time-tracker
npm test
npm run validate
npm run test:ui
node --test ../../plugin/plan-time-tracker/test/*.test.mjs
```

Браузерные проверки используют реальный Worker и изолированную SQLite. Они не создают записи на рабочем сайте. Подробности сборки — в [README приложения](sites/plan-time-tracker/README.md).

## Обновление схемы

`0021_simple_steps.sql` переносит текст этапов в `plan_steps.content`, сохраняет текущие требования без изменения JSON/digest и удаляет таблицы старого исполнения. Обе схемы миграций проверяются на заполненном снимке с открытым интервалом и действующей обученной моделью.

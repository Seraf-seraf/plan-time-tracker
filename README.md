# Трекер планов

Приватный трекер выполнения планов: серверный учёт времени, этапы, попытки и проверки результатов. Несколько планов могут работать одновременно. Общее время считается без двойного учёта пересекающихся интервалов; время каждого плана и их сумма доступны отдельно.

[Открыть трекер](https://plan-time-tracker-v3.seraf-k.chatgpt.site) · [Приложение и API](sites/plan-time-tracker/README.md) · [Инструкция агента](plugin/plan-time-tracker/skills/track-plan/SKILL.md) · [Контракт доказательств](docs/worktree-evidence.md)

## Установка плагина

Нужны Git, Codex CLI с поддержкой плагинов и учётная запись ChatGPT с доступом к приватному Site. Если Codex ещё не установлен, установите его по [официальной инструкции](https://developers.openai.com/codex/cli):

```sh
npm install -g @openai/codex
codex login
codex login status
```

Добавьте marketplace и установите плагин:

```sh
codex plugin marketplace add Seraf-seraf/plan-time-tracker
codex plugin add dev-9529b49da3708191b8f13f1e1e4b1e01@plan-time-tracker
```

Завершите предложенное подключение App и начните новую сессию Codex. В ней вызовите `GetTrackerCapabilities`: ожидается `parallelPlans: true`. Затем вызовите `ListPlans` с `statuses: ["RUNNING"]` и пройдите все страницы по `nextCursor`. Эти вызовы только читают данные. Если инструменты недоступны или вход не работает, сообщите об ошибке; не подставляйте `ownerId` и не обходите аутентификацию.

Видимое имя — «Трекер планов», GitHub-пакет — `3.1.0`. Техническое имя в командах не переводится. Пакет использует единственный корневой [plugin.json](plugin/plan-time-tracker/plugin.json), настройки OpenAI находятся в `extensions.com.openai`. Обнаружение пакета проверено в Codex CLI 0.159.2; совместимость со старыми клиентами, требующими вложенный манифест, не подтверждена.

## Обновление

Повторное `marketplace add` не обновляет уже добавленный Git-снимок. Чтобы получить новый выпуск, выполните команды по порядку; при ошибке остановитесь:

```sh
codex plugin marketplace list --json
codex plugin marketplace upgrade plan-time-tracker
codex plugin add dev-9529b49da3708191b8f13f1e1e4b1e01@plan-time-tracker
codex plugin list --marketplace plan-time-tracker --json
```

`upgrade` обновляет Git-снимок marketplace и при его изменении — кэш настроенных плагинов. Повторный `plugin add` переустанавливает пакет из этого источника. В результате последней команды проверьте запись в `installed`: ожидается версия `3.1.0`. Затем начните новую сессию Codex и повторите проверку MCP-инструментов. Отдельной команды `plugin update` нет; вручную удалять кэш не нужно.

Если по-прежнему устанавливается `2.0.0`, проверьте `source` и `ref` в выводе `marketplace list --json`. Это прежний выпуск; текущий манифест содержит `3.1.0`, а marketplace репозитория не закрепляет `2.0.0`. Причиной может быть старый снимок или другой источник. `upgrade` сохраняет настроенный `ref`, а не переключает ветку или тег на `main`. Если источник локальный, сначала обновите его каталог, сохранив свои изменения, затем повторите `plugin add`: `marketplace upgrade` работает с Git-источниками.

## Как работает учёт

[track-plan](plugin/plan-time-tracker/skills/track-plan/SKILL.md) требует вести учёт при выполнении любого разрешённого пользователем плана, даже без отдельной просьбы использовать трекер. Составление и обсуждение плана не запускают таймер. Просьба выполнить план разрешает его регистрацию и запуск, просьба продолжить — возобновление. Пауза и завершение требуют соответствующего намерения пользователя; конец ответа и истечение аренды попытки не останавливают время.

MCP и веб-интерфейс используют одни команды. Каждому исполнителю нужен свой контекст плана, этапа, попытки, сессии и очереди. Без аутентифицированного трекера выполнение с обязательным учётом блокируется. MCP не перехватывает работу клиентов, которые его не вызывают. Репозиторий, синхронизация, интеграция с commit/push и внешний токен для учёта не требуются.

`ListPlans({statuses, limit, cursor})` возвращает `{plans, nextCursor, serverNow}`. Размер страницы — 50 по умолчанию, максимум 100; порядок — по убыванию `registeredAt`, затем `planId`. Активных планов может быть несколько. Продолжайте известные PAUSED/PLANNED по явному ID без дубликатов.

`totalActiveMs` и `activeByDay` считают объединение интервалов владельца, `sumPlanActiveMs` — сумму длительностей планов. Например, два часовых плана 10:00–11:00 и 10:30–11:30 дают сумму 120 минут и общее время 90 минут. Проверки привязаны к текущей ревизии результата и снимку исходников; подробные правила завершения — в инструкции агента.

### Локальные скрипты

Тесты запускаются из каталога `plugin/plan-time-tracker`:

```sh
node --test test/*.test.mjs
```

Синтаксис снимка из того же каталога: `node scripts/source-snapshot.mjs <source-directory> [--expect sha256:64hex]`. Замените `<source-directory>` путём к исходникам; необязательный `--expect` принимает digest ранее созданного снимка. Скрипт создаёт детерминированный снимок v2 без внешних программ. Храните доказательства вне каталога исходников, передавайте `sourceSnapshot` без локального `fileCount`. Для проверок используйте `testedSnapshotDigest` и точную ревизию результата. Состав снимка и исключения описаны в [контракте](docs/worktree-evidence.md).

`plugin/plan-time-tracker/scripts/observation-queue.mjs` принимает JSON через stdin и операцию `enqueue`, `next`, `begin`, `acknowledge`, `fail`, `requeue-pending` или `list`. Укажите полученный после аутентификации `ownerScope` и `planContext` — ID назначенного плана. Скрипт хранит очередь только локально; не выполняет вход, сетевые вызовы или изменения жизненного цикла. Старые очереди, привязанные к репозиторию, автоматически не воспроизводятся. Тесты используют синтетические данные и временные каталоги; учётные данные и обход аутентификации в пакет не включены.

## Удаление и восстановление

Кнопка «Удалить» в карточке или деталях плана просит подтверждение и переносит план в «Удалённые». История, этапы и результаты сохраняются. Активный интервал закрывается сервером, открытые попытки завершаются как ABANDONED. Удалённые планы не попадают в обычный список и аналитику; их детали доступны только для чтения.

В разделе «Удалённые» можно восстановить план. Выполнявшийся план вернётся на паузу, остальные сохранят свой статус. Восстановление не запускает таймер и не возвращает старые попытки: для работы нужны явное продолжение и новая попытка. Завершённые результаты и проверки сохраняются. Удалённый период не добавляет активного времени; после восстановления календарная длительность по-прежнему включает прошедшие паузы.

В MCP доступны `DeletePlan` и `RestorePlan`: `schemaVersion: 1`, новый UUID `commandId`, текущая `expectedVersion` и `payload: {planId, reason?}`. Они требуют отдельной просьбы пользователя. `GetPlan` показывает `deletedAt` (null у обычного плана), `ListPlans` по умолчанию исключает удалённые; `deleted: true` выбирает только их. При неизвестном ответе повторяйте тот же конверт, а при конфликте версии перечитайте состояние. Экспорт сохраняет и удалённые планы.

Для выпуска 3.1.0 нужны миграция `0016_plan_deletion.sql`, совместимый Worker и обновление MCP discovery. На существующей параллельной v3-базе применяют только новую миграцию, без сброса данных. Подробный [контракт API](sites/plan-time-tracker/README.md#удаление-и-восстановление-планов-310) описывает ошибки и порядок обновления.

Выберите один источник с именем `plan-time-tracker`. Локальная установка использует App из [.app.json](plugin/plan-time-tracker/.app.json) — `asdk_app_sites_ae77444ef43481919c2588ef24f70c84`; она не запускает сервер и не выдаёт доступ к чужому приватному Site.

В ChatGPT установите доступный вам собственный плагин через каталог Plugins, подключите App и начните новый чат. Отдельный плагин Site имеет ID `plugin_asdk_app_sites_ae77444ef43481919c2588ef24f70c84` и версию `3.0.0`. Старые подключения к предыдущему Site автоматически не переключаются.

GitHub marketplace распространяет пакет, но не публикует его в общем каталоге и не открывает Site другим пользователям. Для общего каталога нужна отдельная [подача на проверку](https://developers.openai.com/plugins/deploy/submission). Доступ к приватному App настраивается отдельно.

## Сборка и проверки

Нужны Node.js 24, npm, Bash и `tar`. Node.js 24 — проверенная версия; минимальная в `package.json` не задана. Зависимостей и lockfile у приложения нет, поэтому `npm install` и `npm ci` не нужны.

Для нового клона:

```sh
git clone https://github.com/Seraf-seraf/plan-time-tracker.git
cd plan-time-tracker
```

Из корня выбранного checkout:

```sh
git remote -v
git status --short --branch
git rev-parse HEAD
cd sites/plan-time-tracker
npm run build
npm run validate
npm test
node --test ../../plugin/plan-time-tracker/test/*.test.mjs
```

Build пересоздаёт `dist/`: копирует Worker в `dist/server/index.js`, а конфигурацию — в `dist/.openai/hosting.json`. Worker содержит UI и MCP endpoint `/mcp`. `validate` проверяет ESM и экспорт `default.fetch`. Тесты приложения используют SQLite в памяти; тесты плагина проверяют единственный manifest, App-привязку и упаковку через `tar`.

Браузерные проверки требуют Playwright и Chromium; команда и переменные `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE`, `UI_ACCEPTANCE_ARTIFACT_DIR` описаны в [README приложения](sites/plan-time-tracker/README.md#local-verification). Локальные тесты не проверяют вход и рабочую D1 в Sites.

## Развёртывание Site

Приложение размещается в ChatGPT Sites на Cloudflare Worker с D1. Нужны права владельца или редактора проекта и подключённые инструменты Sites. Текущий проект указан в [hosting.json](sites/plan-time-tracker/.openai/hosting.json): `appgprj_6ad342fe722481919f98177e1c447931`, привязка D1 — `DB`, возможности — `["mcp"]`, R2 не используется.

Строковые переменные среды, `.env`, GitHub PAT, OpenAI API key и `DATABASE_URL` приложению не нужны. Worker получает объект `env.DB` от хостинга и доверенные заголовки входа `oai-authenticated-user-id` / `oai-authenticated-user-email` от Sites. Для другого хостинга потребуется отдельный доверенный слой аутентификации; не подставляйте эти заголовки вручную.

### Миграции

Новой установке v3 нужна пустая D1 с привязкой `DB` и все 16 SQL-файлов из [drizzle](sites/plan-time-tracker/drizzle), применённые в порядке имён от `0001_initial.sql` до `0016_plan_deletion.sql`. Старая база с ограничением на один RUNNING-план этим выпуском не обновляется. Не повторяйте начальную цепочку на рабочей базе и не обнуляйте уже подготовленную v3-базу при публикации.

**Блокер новой установки:** подтверждённой команды применения SQL к hosted Sites D1 здесь нет; build не выполняет миграции, а `read_database_overview` только читает схему — до публикации владелец должен применить цепочку поддерживаемым способом и подтвердить схему.

### Публикация

Дальше используются инструменты подключённого Sites, а не shell-команды:

1. Прочитайте манифест хостинга и проверьте проект через `get_site`. Для обновления используйте его `project_id` и сохраните приватный доступ. Для независимой установки подготовьте отдельную копию без привязки к чужому проекту, создайте свой Site через `create_site`, сохраните возвращённый ID и настройте собственную App-привязку.
2. Убедитесь, что D1 подготовлена. У существующего v3-проекта проверьте привязку `DB` и схему через `read_database_overview`.
3. Подготовьте исходники в репозитории исходников, подключённом к Site: он может отличаться от GitHub `origin`. При необходимости `create_source_repository_write_credential` вернёт `remote_url`, `branch` и краткоживущий token. Не сохраняйте token в remote URL, документах, логах или архиве; для явной публикации не запрашивайте `publish_on_push`.
4. В рамках выпуска зафиксируйте и отправьте точное состояние в ветку исходников Site. Соберите и проверьте этот checkout командами выше. `commit_sha` должен быть полным SHA текущей HEAD этой удалённой ветки.
5. Из `sites/plan-time-tracker` упакуйте содержимое `dist/`, включая скрытый `.openai`:

   ```sh
   tracker_archive_dir=$(mktemp -d)
   tar -czf "$tracker_archive_dir/plan-time-tracker.tar.gz" -C dist .
   tar -tzf "$tracker_archive_dir/plan-time-tracker.tar.gz"
   ```

   В архиве должны быть `./server/index.js` и `./.openai/hosting.json`. Исходники, `.git`, учётные данные и миграции в него не входят. Сохраните абсолютный путь к архиву до окончания загрузки.
6. Вызовите `save_site_version` с `project_id`, `commit_sha` и абсолютным путём `archive`. Сохраните возвращённый `id` как `version_id`.
7. Для подтверждённого приватного проекта вызовите `deploy_private_site_version` с `project_id` и `version_id`. Если аудитория не совпадает, остановитесь. Проверяйте `get_deployment_status` по возвращённому deployment ID до `succeeded` или `failed`: URL публикации ведёт на рабочий сайт.
8. После успеха проверьте вход владельца в UI, `GetTrackerCapabilities` и все страницы `ListPlans`. Обновите плагин и обнаружение инструментов в клиентах отдельно.

Обновление GitHub не развёртывает Worker и не обновляет установленный плагин. Готовой команды `npm run deploy` в репозитории нет. Подробнее: [публикация и доступ в Sites](https://learn.chatgpt.com/docs/sites/publishing-and-sharing).

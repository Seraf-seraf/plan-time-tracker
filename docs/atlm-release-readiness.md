## Проверки реализации

Основной набор `npm test`: **304/304**. `npm run validate` проходит. Пакет навыков `node --test test/*.test.mjs`: **17/17**. Среда: Node 24.19.0, Python 3.12.14, установленный Playwright и Chromium.

Численные ожидания проверены по независимым OLS-фикстурам. Отдельный ревьюер воспроизвёл и проверил исправления полноты времени после удаления/восстановления, сброса retry-бюджета новой generation, cutoff снимка, задержек после истёкшего lease, гонки захвата, исчерпания бюджета перед fit, размера серверной оценки и окончательных квитанций отказа.

`test/atlm-artifact-lifecycle.test.js` выполняет весь сценарий через публичные команды и MCP собранного Worker: 15 последовательных принятых планов, настоящие исходные оценки, серверные интервалы и проверки, автоматическое обучение через `ctx.waitUntil`, модель на всех 15 примерах и сохранённый прогноз следующего плана. Модель и samples не вставляются напрямую в SQL. После выполнения прогноз сохраняется неизменным. Проверка прошла для GitHub artifact и отдельно собранного Sites artifact.

Наборы хранения и обучения проверяют атомарный первый запуск, A→B→A, отсутствие повторного опыта, незавершённые/непроверенные источники, поздние проверки, сохранение состояния после перезапуска БД, lease/fence, конкурирующие завершения, инвалидацию, отклонение худшего кандидата, все четыре попытки и задержки 1/5/15 минут. API-проверки покрывают реальные HTTP/MCP схемы, доступ владельца, постраничный снимок, ошибку источника и запрет выдачи ошибки сервиса за отсутствие данных.

Браузерная приёмка охватывает новый прогноз, отсутствие модели, ошибки и повторы, устаревание, отклонённого кандидата, поздний ответ другого плана, ограниченное продолжение очереди, клавиатуру и ширины 320/390/768/1440. Первый сценарий использует настоящий Worker и SQLite; управляемые ответы затем проверяют редкие состояния и гонки интерфейса. Скриншоты начального состояния и адаптивных экранов просмотрены. Полный `npm run test:ui` прошёл: **9/9 наборов**, включая прежние таймеры, результаты, восстановление, аналитику, параллельные планы, удаление, пагинацию и ленивую историю.

В прежних UI-тестах обновлены тестовые адаптеры: D1 `batch` выполняется атомарно, а разрешённый POST обработки очереди отделён от команд плана. Для аналитики очередь обрабатывается при подготовке, затем проверяются только GET и неизменность всей БД. Неожиданные 5xx не игнорируются. ## Ресурсы и пределы доказательств

Численное ядро дополнительно измерено в изолированном **workerd 1.20261110.1**, compatibility date `2026-11-10`, на синтетических данных. CPU — время всего процесса Linux с дискретностью счётчика 10 мс, усреднённое по повторным операциям; таблица содержит медианы. Это не данные владельца и не измерение production D1.

| Примеров | Fit, CPU мс | Один проверочный случай, CPU мс | 20 случаев, CPU мс | Размер модели, байт |
| --- | --- | --- | --- | --- |
| 50 | 2 | 2 | 30 | 4364 |
| 200 | 4 | 4 | 70 | 12072 |
| 1000 | 18 | 18 | 360 | 52078 |
| 5000 | 82 | 94 | 1980 | 252087 |

При 5000 строках полная историческая проверка заняла около 1,93 с wall time. Максимальный RSS всего процесса — около 183 MiB, включая движок; это не размер JS heap отдельного isolate. Измерялось неизменённое численное ядро до подключения HTTP/UI; результат не включает D1 и весь жизненный цикл обучения.

Квоты CPU/памяти существующего hosted Sites не раскрыты доступной конфигурацией и этим замером не подтверждены. Ограниченный проход и checkpoints позволяют сохранять прогресс; после исчерпания ресурса или аварии очередь восстанавливается с ограничением повторов при следующем взаимодействии. Гарантированный таймер без новых запросов в v1 отсутствует. При превышении 5000 пригодных текущих примеров выдаётся явный предел без удаления опыта или скрытого усечения.

Старые планы без признаков, сохранённых до первого запуска, не становятся обучающими примерами задним числом. Пять новых планов означают частоту попыток, а не обещание готовой первой модели. Синтетические тесты доказывают работу механизма; точность на реальной работе агентов требует накопления и отдельной перспективной проверки. Точка ATLM не является P50/P80 или гарантированным интервалом.

Откат кода использует сохранённую версию Sites и сохраняет добавленные таблицы, модели, прогнозы и опыт. Этот выпуск не добавляет API ручного переключения моделей. В production не создаются демонстрационные планы ради обучения. Внешняя CI-проверка не заявляется: в репозитории нет настроенного workflow CI.

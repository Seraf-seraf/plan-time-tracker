# Гибридный прогноз ATLM

ATLM прогнозирует полное активное время плана PLAN_ACTIVE от первого StartPlan. Метод `atlm/agent-v3-hybrid` сравнивает обычную регрессию OLS и ridge по ошибкам на прошлых задачах. Если обучаемый прогноз неприменим, сервер может вернуть явно обозначенный `historical-median/version1`. Медиана не называется обученной ATLM.

Результат обучения — измеренное время завершённых задач. Сохранённые прогнозы нужны для проверки ранее выданных оценок и не заменяют факты. Новая версия алгоритма не меняет исходные признаки, assessment revisions и frozen-прогнозы начатых планов. Новая миграция D1 не требуется.

## Девять исходных признаков

Вход остаётся `agent-task-v1`, схема вычисленных признаков — `agent-task-v2`.

| Признак | Значение |
| --- | --- |
| workKind | Вид работы |
| reuseState | Готовность существующего решения |
| doneBoundary | Требуемая граница результата |
| outcomeCount | Число уникальных требуемых результатов |
| contractCount | Число уникальных изменяемых контрактов |
| verificationKindCount | Число видов необходимых проверок |
| modelId | Модель агента либо неизвестное значение |
| reasoningEffort | Уровень размышлений либо неизвестное значение |
| plannedParallelAgents | Число параллельных агентов, не меньше 1, либо неизвестное значение |

Сервер получает profile, outcomes, changedContracts, verificationKinds и profileEvidence в AgentTaskV1. Счётчики вычисляются после нормализации/устранения точных дублей списков; клиент не передаёт готовые счётчики. До 20 outcomes, 20 changedContracts и пяти видов проверки. Противоречащие описания одного ключа запрещены. Неполные первые шесть признаков дают INCOMPLETE_FEATURES, подтверждённые пустые списки дают настоящий ноль. Текущий статус плана не является исходным признаком.

modelId/reasoningEffort/plannedParallelAgents неизвестны независимо друг от друга; это не препятствие обучению. Модель и уровень размышлений — номинальные категории, а не числовой рейтинг. null становится отдельным уровнем, если встречался в обучении. Новая runtime-категория использует этот уровень; если его не было — взвешенное обучающими частотами представление известных уровней до обратного преобразования времени. plannedParallelAgents центрируется по среднему преобразованных известных значений; неизвестное получает нулевое отклонение и индикатор пропуска. Неизвестное не превращается в ноль агентов или угаданную модель. environmentId/provenance сохраняют прежний смысл метаданных и не становятся дополнительными признаками.

## Фактическое время и пригодность

StartPlan/ResumePlan открывают рабочий интервал, PausePlan/FinishPlan закрывают. readAtlmSampleSource сверяет полную историю интервалов с серверными квитанциями и записывает в actualMs длительность их объединения. Промежутки пауз исключаются. Ожидание с включённым таймером входит в PLAN_ACTIVE; это не процессорное время агента.

Пригоден завершённый не удалённый план с полными обязательными исходными признаками, исходным снимком до первого запуска, DONE у всех этапов, полным измерением и неизменным объёмом. Изменение требований A→B→A также является изменением объёма. Продолжительность сама по себе не служит причиной исключения; нулевой измеренный факт допустим.

Версии samples неизменяемы. Для текущего обучения сначала выбирается последняя версия каждого плана среди всех статусов, затем eligibility. Иначе можно ошибочно вернуть исключённый источник через его старую пригодную версию. Один planId даёт не более одной единицы нового опыта за всё время; новый Finish, восстановление или ревизия не создают новый план.

Новый пригодный факт входит в следующее полное обучение на всех актуальных пригодных планах. Два новых уникальных пригодных плана — частота автоматической попытки, а не достаточное число примеров для точного прогноза. Повторяющиеся реальные задачи не удаляются и не перевзвешиваются. Много похожих задач не доказывает качество на другой работе.

## Два обучаемых решателя

OLS agent-v2 сохранён как отдельные fitAtlmOls/predictAtlmOls с прежними численными результатами. Основа — [Whigham, Owen, MacDonell: A Baseline Model for Software Effort Estimation](https://arxiv.org/abs/2102.02933): OLS, выбор identity/log/sqrt и кодирование категорий. Внутреннее время — минуты, внешний API — целые ms. Преобразования выбираются только на обучающей истории. log требует положительных значений, sqrt — неотрицательных; скрытого +1 нет.

OLS требует n>=p и полного ранга. Ранг — число независимо различимых направлений влияния признаков: если MODIFY_MECHANISM всегда совпадает с PARTIAL, история не разделяет их поправки. Дополнительные задачи с тем же сочетанием эту зависимость не устраняют. QR с перестановкой и выравниванием столбцов сохраняет прежние явные отказы RANK_DEFICIENT/INSUFFICIENT_DATA.

Ridge использует все девять признаков. Каждый наблюдавшийся категориальный уровень имеет собственный столбец. Числовые столбцы после преобразования центрируются и масштабируются по обучающей истории, категориальные не делятся на частотное стандартное отклонение. Для констант масштаб равен 1. Эти параметры хранятся только в артефакте, исходные значения не переписываются.

Политика 1 фиксирует lambda=1 и функцию потерь: средний квадрат ошибки плюс lambda × сумма квадратов поправок. Свободный член не штрафуется. При совпадающих столбцах можно увеличить одну поправку и уменьшить другую без изменения прогноза; ridge ограничивает такие большие поправки. Расчёт выполняется QR расширенной системы, без обращения X'X. Математические строки штрафа не считаются реальными примерами, не входят в n/manifest и не создают actualMs. Ridge допускает недостаточный исходный ранг и n<p; это устраняет вычислительную блокировку, но не добавляет отсутствующую информацию о влиянии признаков.

Автоматического подбора lambda нет. Её изменение требует новой версии политики и проверки всего правила выбора. Обратное преобразование, округление до ms и конечность/неотрицательность проверяются; отрицательное или NaN не становится нулевой длительностью. Предел каждой ветви — 64 столбца, истории обучения — 5000 реальных строк. История и категории не усекаются молча. Отказ одной ветви не запрещает доступную другую.

## Выбор метода

На момент обучения сервер строит OLS и ridge и сравнивает стратегии OLS → ridge → медиана и ridge → медиана с простой медианой. Сравнение использует одни и те же до 20 последних доступных проверочных случаев; ошибки подстраховки также учитываются.

Для подтверждённого выбора ветвь должна сейчас рассчитываться и иметь минимум пять собственных исторических прогнозов, сравнимых с медианой. Подстраховка ridge не засчитывается как собственный OLS. Полный ранг разрешает расчёт OLS, но не даёт ему приоритета.

Выбирается меньшая средняя абсолютная ошибка в ms. Сначала определяется общий минимум, затем среди вариантов в пределах 1 ms от него действует порядок: медиана, ridge, OLS. Пока пригодных собственных сравнений недостаточно, ранний вариант — доступный ridge, затем OLS, затем медиана; обученный результат помечается EXPERIMENTAL.

Если предпочтительна медиана, новый кандидат не активируется, причина — MEDIAN_BASELINE_NOT_WORSE. Действующая пригодная модель сохраняется по защите incumbent. Если действующей применимой модели нет, доступен historical-median. Худший/неподтверждённый кандидат не заменяет подтверждённый incumbent. Замена использует минимум пять новых сравнений, не входивших в обучение incumbent, и сопоставимое собственное покрытие.

Артефакт фиксирует выбор решателя; запрос прогноза не обучает и не меняет его. Выбранный OLS при расчётной неприменимости точки использует сохранённый ridge, затем медиану; выбранный ridge — медиану. Неизвестная обязательная категория не угадывается. INVALID_PREDICTION корректного артефакта может дать медиану, но повреждённый артефакт, неверный вход, авторизация, БД и ресурсные ограничения не маскируются успешным числом.

## Проверка всей политики без будущих данных

Протокол 1 остаётся воспроизводимой проверкой старого OLS. Протокол 2 проверяет целый гибрид. Для задачи q берутся только версии с observedAt<q.capturedAt; выбирается последняя наблюдавшаяся версия плана, затем проверяются eligibility и sourceAvailableAt<q.capturedAt. Текущий planId исключён, равенство временной границе означает недоступность. Будущая версия не видна; старый факт не теряется только потому, что после q появился новый sample.

Для каждого внешнего случая заново применяется выбор метода по ещё более ранним проверкам. Факт самого внешнего случая используется только после формирования прогноза. Нельзя выбрать победителя по всему внешнему окну и назвать ошибку того же победителя независимой проверкой. Преобразования/масштабы также вычисляются только на соответствующем префиксе. Параллельный план без уже наблюдавшегося готового факта не является обучающим примером.

cases сохраняют собственные atlm/ols/ridge и median, отдельное prediction содержит доставленный прогноз с подстраховкой. metrics.atlm — ошибка собственных прогнозов, metrics.operational — ошибка целой политики; paired остаётся отдельной диагностикой. Публичная evaluation нового метода содержит metricsScope=FULL_POLICY, caseCount полного сравнения, modelCaseCount, собственное coverage, operationalCoverage, сопоставимые maeMs/medianBaselineMaeMs и profileGroupCount. Случай без истории не становится нулём и одинаково исключается из ошибок сравниваемых методов.

qualityConfirmed требует не менее пяти внешних обученных прогнозов, ошибки целой политики не хуже медианы и принятого сравнения с incumbent. Пять проверок — технический минимум, не гарантия независимости и будущей точности. Число групп одинаковых шести основных признаков помогает увидеть похожие серии; оно не меняет вес задач. Старые paired-метрики протокола 1 не переименовываются задним числом в FULL_POLICY.

Эта ретроспектива проверяет обучение на доступном префиксе перед задачей, не точное расписание очереди через каждые два плана. Ошибка реально выданного frozen-прогноза учитывается отдельно и отражает фактическую задержку обновления модели.

## Хранение и очередь

В estimation_models сохраняется новый неизменяемый артефакт formatVersion=2/kind=HYBRID/method=atlm/agent-v3-hybrid/policyVersion=1: выбранный решатель, n/p/rank, manifest, digest, cutoff, решение и артефакты ветвей. Ridge имеет внутренний kind=RIDGE/method=atlm-ridge/1, lambda/objective, уровни, частоты, центры/масштабы и коэффициенты. OLS сохраняет прежний артефакт agent-v2. Ограничение rank=p относится только к OLS; n-p у ridge не объявляется оценкой неопределённости.

Корректная активная agent-v2/agent-task-v2 модель остаётся читаемой и пригодной для защищённой записи прогноза до принятия замены. Исторические frozen-оценки любых сохранённых версий читаются без нового расчёта. Новые модели записываются в существующие JSON-поля; SQL 0001–0024, старые модели/метрики/признаки не переписываются.

Snapshot фиксирует текущий manifest итогового обучения, asOf/historyThroughSequence исторического журнала и cutoff. Исторические версии проверки не обязаны оставаться текущими ELIGIBLE, но итоговый manifest при активации обязан быть актуальным и чистым. Очередь сохраняет lease 60 s, fencing token, ограниченные проходы до 10 s wall time, checkpoint и повторы 1/5/15 минут до четырёх попыток. Результаты базовых проверок сохраняются между проходами; матрицы всех префиксов в checkpoint не копируются. Несовместимый старый checkpoint не трактуется как новый протокол.

Изменение использованного источника инвалидирует зависящую модель и ставит пересборку независимо от пары новых планов. Старый исполнитель не активирует результат после передачи владения. Ошибка обучения не отменяет успешную запись времени. ctx.waitUntil и ограниченное продолжение через UI/MCP сохраняются; без новых обращений гарантированного восстановления нет, cron не устанавливается. Локальный wall-time budget не является подтверждением CPU-лимита опубликованного Sites.

## MCP, HTTP и сохранение прогноза

Имена обнаруживаются через GetTrackerInfo.assessments.atlm. Внешние конверты не меняются: schemaVersion=1 команд, formatVersion=1 serverEstimation, predictionRequest={method:"ATLM",methodVersion:1}. Клиент не передаёт serverEstimation, коэффициенты, длительности примеров, lambda или предпочтительный решатель.

| Инструмент | Назначение |
| --- | --- |
| EstimatePlanTime | Read-only прогноз по AgentTaskV1 до старта; POST /api/tracker/atlm-estimate |
| GetSavedEstimate | Текущий read-only расчёт PLANNED или frozen после старта; GET /api/tracker/plans/:planId/estimate |
| GetTrainingStatus | Счётчики, модель, очередь и диагностика; GET /api/tracker/estimation-model |
| StartTraining | По прямой просьбе пользователя попытка без ожидания пары новых планов; POST /api/tracker/estimation-model/start |
| ContinueTraining | Ограниченный проход очереди; POST /api/tracker/estimation-model/process |
| GetTrainingData | Read-only страницы неизменяемого журнала; POST /api/tracker/atlm-dataset |

serverEstimation содержит method, nullable pointMs/modelId/modelVersion, sampleCount, evaluation, accuracy, digests/calculatedAt, interval=null и confidence=UNKNOWN. Новый обученный прогноз добавляет необязательный hybrid={policyVersion,selectedEngine,usedEngine,fallbackReason}; usedEngine описывает фактически использованную ветвь. Медиана сохраняет отдельный method, modelId=null и HISTORICAL_BASELINE. Точка не называется P50/P80 или гарантированным интервалом.

GetSavedEstimate до первого запуска возвращает source=CURRENT_INPUT по последней полной assessment и текущим фактам. recordedEstimation сохраняет первоначальную оценку отдельно для аудита. GET не пишет assessment/таймер и не обучает. Первый StartPlan атомарно сохраняет текущую оценку и признаки в plan_estimation_inputs через receipt/CAS. RUNNING/PAUSED/COMPLETED читают прежний frozen-снимок; ResumePlan/поздняя assessment его не заменяют. forecast_json=NULL у legacy-строк означает чтение исходной assessment без пересчёта. Гонки дают ограниченный повтор либо явную ошибку, без старта с недоказанным новым снимком.

Новые issuedPrediction фиксируют method, nullable modelId/modelVersion, calculatedAt, pointMs, optional hybrid и фактические actualMs/errorMs, включая ранее выданную медиану. Старые версии sample не изменяются, массовый backfill не выполняется. Даже при issuedPrediction=null пригодный measured actualMs используется для обучения. Сохранённый прогноз не подменяется новым после завершения задачи.

GetTrainingStatus.lastAttempt — снимок своей попытки/datasetRevision, не вывод из текущего числа пригодных планов. candidates содержит отдельные безопасные статусы/причины/размеры ветвей, selection — результат выбора. RANK_DEFICIENT у OLS не является отказом всего гибрида. Детали коэффициентов/исходных планов не попадают в публичную диагностику. Интерфейс показывает реально использованный метод, качество и ошибку всей политики; технические p/rank доступны в раскрываемых подробностях. Исходные оценки COMPLETED/удалённых доступны через API, рабочая плашка для них не показывается.

## Локальная проверка экспорта

GetTrainingData возвращает все sample-версии, а не только актуальные: formatVersion=1, datasetRevision, asOf, rows, hasMore, nextCursor. Передавать nextCursor до конца; datasetRevision/asOf должны совпадать. DATASET_CHANGED требует начать чтение заново. Сырые планы, ID и данные владельца не добавляются в Git.

CLI `scripts/evaluate-atlm.mjs` ничего не пишет на сервер. Прежний вход formatVersion=1 с нормализованными latest-only rows и sourceAuthority=SYNTHETIC/OWNER_EXPORT сохраняет протокол 1. Его нельзя объявлять полным журналом протокола 2.

Новый вход: formatVersion=2, sourceAuthority=OWNER_EXPORT, datasetRevision, asOf, throughSequence, nextCursor=null и rows всех версий из полной выгрузки. Строки упорядочены по числовому sampleId, последняя граница равна throughSequence. Нельзя смешивать страницы, заранее отбрасывать EXCLUDED или передавать только часть журнала. Проверяются формат, времена, дубли и предел 8 MiB; значения признаков/фактов не исправляются для запуска обучения.

```sh
# Из sites/plan-time-tracker; оба пути находятся вне Git.
node scripts/evaluate-atlm.mjs "$ATLM_HYBRID_DATASET" > "$ATLM_HYBRID_REPORT"
```

Отчёт содержит ошибки OLS/ridge, собственное и операционное покрытие, ошибку целого гибрида и медианы на одинаковых случаях, причины пропусков, cutoff и ограничения разнообразия. Реальная полезность оценивается на фактической истории; существующие синтетические фикстуры проверяют контракт реализации, а не точность на задачах владельца.

Для браузера нужны Playwright и Chromium; PLAYWRIGHT_MODULE может указывать абсолютный путь к index.mjs, CHROMIUM_EXECUTABLE — к браузеру. UI_ACCEPTANCE_ARTIFACT_DIR задаёт каталог снимков вне Git. Тесты используют локальный Worker и изолированную SQLite, не рабочий Site.

Локальная реализация, GitHub, CI, публикация Site и установка hosted-плагина — разные результаты. Новый method/policy версионирует алгоритм без изменения внешнего входа; местная сборка сама по себе не публикует код и не запускает обучение владельца. Фактические результаты этой реализации — в [локальной приёмке гибрида](atlm-hybrid-verification.md); прежний [отчёт выпуска](atlm-release-readiness.md) остаётся историческим.

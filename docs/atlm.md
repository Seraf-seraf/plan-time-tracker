# ATLM: прогноз активного времени

ATLM прогнозирует `PLAN_ACTIVE`: полное время рабочих интервалов плана без пауз, начиная с первого StartPlan. Это не календарный срок и не сумма времени параллельных исполнителей. До запуска GetSavedEstimate читает текущий прогноз без записи; первый StartPlan атомарно фиксирует его. После запуска показывается сохранённый снимок и признак устаревания при изменении источника.

До начала работы заполните признаки по схеме `agent-task-v4`. Полную схему с вложенными полями, допустимыми значениями и ограничениями возвращает `GetTrackerInfo` в `assessments.atlm.agentTaskSchema`. Её используют оба входа, `EstimatePlanTime.agentTask` и `SaveTaskAssessment.payload.context.agentTask`. Если клиент сокращает объявление инструмента, читайте сам ответ `GetTrackerInfo`. [Справочник признаков и примеры](../plugin/plan-time-tracker/skills/assess-task/references/features.md).

Сервер рассчитывает счётчики и долю операций WRITE, кодирует категории и отличает неизвестные значения от подтверждённых нулей. Интерфейс показывает названия признаков, их значения и сохранённые причины неизвестности. Для первого `StartPlan` требуется оценка со статусом `READY`. Снимок может содержать доступный прогноз или `UNAVAILABLE`, если данных для него недостаточно. [Запись оценки и проверка готовности](assessments.md).

## Расчёт

Метод `atlm/agent-v5-operations` использует преобразование `log1p(actualMs / 60000)` и сравнивает OLS, Ridge и Bayesian с исторической медианой. Ridge и Bayesian могут работать при числе признаков не меньше числа наблюдений; OLS требует полного ранга. Точечный метод выбирается отдельно от интервального. При нулевой истории прогноза нет; при одном пригодном плане возвращается `historical-median` без интервала. Начиная с двух примеров возможен экспериментальный прогноз модели.

Bayesian использует normal-inverse-gamma и прогнозное распределение Student-t с фиксированными приорами: precision 1 для стандартизованных коэффициентов и 0,000001 для свободного члена, shape 2, scale 1. `BAYESIAN_PREDICTIVE` выдаёт квантили 0,10 и 0,90. `BAYES_QUANTILE` обучает регуляризованные квантильные регрессии 0,10/0,50/0,90 на стандартизованных остатках исторического Bayesian; для каждого остатка и преобразования признаков используются только факты, доступные до начала задачи. Нужно не менее пяти таких остатков. Пересечённые квантили упорядочиваются, а границы расширяются до выбранной точки.

В `serverEstimation` находятся `pointMs`, `pointEngine` и `interval` с `status`, `lowerMs`, `upperMs`, `nominalCoverage`, `engine`, `calibrationSampleCount`, `validationStatus`, `unavailableReason`. При недоступном диапазоне границы null и указана причина. Номинальный охват 0,80 — цель, а не гарантия будущего результата. EXPERIMENTAL и HISTORICALLY_EVALUATED описывают наличие исторической проверки, а не обещание точности.

## Проверка и обучение

Единица наблюдения — planId. Требуются завершённый проверенный план, исходные признаки, полное измерение и неизменившиеся требования. Повторная ревизия не становится отдельной задачей. Для каждого исторического случая replay использует только источники с `sourceAvailableAt` строго раньше начала задачи и воспроизводит выбор на том же префиксе.

Окно сравнения — последние 20 пригодных случаев. Методы сравниваются на общих случаях: точка по MAE, при равенстве в пределах 1 мс по модулю смещения и затем с предпочтением действующего метода; интервал — по средней интервальной оценке, близости охвата к 0,80 и ширине. Нужно не менее пяти общих честных прогнозов; неподтверждённый кандидат не заменяет действующую модель.

`forecastRate` — доля случаев с точкой; `intervalAvailabilityRate` — доля с диапазоном; `intervalCoverage` — попадания факта среди доступных диапазонов. `maeMs`, `medaeMs`, `meanSignedErrorMs`, `wapePercent`, `signedBiasPercent`, `meanIntervalWidthMs` и `meanIntervalScore` считаются в исходных единицах; при нулевом знаменателе результат null. Знак ошибки: прогноз минус факт.

После каждых двух новых пригодных planId сервер ставит обучение в очередь. StartTraining запускает попытку по прямому запросу, ContinueTraining выполняет ограниченный проход. Просмотр и GET не запускают обучение. Lease, fence и контрольные точки позволяют продолжить работу после прерывания; неудачный кандидат сохраняет действующую модель. Численные лимиты могут вернуть явную причину `MODEL_RESOURCE_LIMIT`, `QUANTILE_RESOURCE_LIMIT`, `QUANTILE_NOT_CONVERGED` или `TRAINING_TIME_BUDGET` без усечения признаков.

GetTrainingStatus показывает состояние, GetTrainingData — версии примеров, GetTrainingHistory — попытки с результатом и диагностикой. Курсоры привязаны к владельцу; при изменении ранее открытого снимка следует начать чтение заново. HTTP история доступна через `GET /api/tracker/estimation-training-history`.

Для планов без сохранённого исходного снимка после сброса истории `GetSavedEstimate` возвращает `HISTORY_RESET`. Возобновление начатого плана доступно и в этом состоянии.

## Хранение и запись

Обученный артефакт остаётся JSON в `estimation_models.artifact_json`; вычисления выполняет JavaScript. Снимок первого запуска, обновление источников, счётчики samples и очистка checkpoint выполняются явными наблюдателями приложения внутри транзакции соответствующей команды или операции обучения. Один изменивший источник commandId создаёт одно обновление поколения; повтор команды и прежние значения не создают лишних обновлений. Прямая запись SQL не запускает эти действия автоматически. [Владельцы поведения, транзакции и переход схемы](application-transactions.md).

## Локальная оценка

Чтобы подготовить журнал для `node scripts/evaluate-atlm.mjs <dataset.json>`, прочитайте все страницы GetTrainingData, последовательно передавая `nextCursor` до null. Убедитесь, что `datasetRevision` и `asOf` одинаковы; при `DATASET_CHANGED` начните сначала. Объедините `rows` в порядке страниц и создайте JSON-обёртку `{formatVersion:3, sourceAuthority:"OWNER_EXPORT", datasetRevision, asOf, throughSequence, nextCursor:null, rows}`. `throughSequence` — числовой `sampleId` последней строки либо 0 для пустого журнала. CLI проверяет порядок и границу, но не может доказать, что при ручном объединении не пропущена промежуточная страница. Протокол оценки — 3, политика выбора — 2, модельный артефакт — 3. Файл не изменяется. Синтетические проверки подтверждают поведение, но не доказывают улучшение точности на реальных задачах.

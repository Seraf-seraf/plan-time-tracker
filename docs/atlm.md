# ATLM: прогноз активного времени

ATLM прогнозирует `PLAN_ACTIVE`: полное время рабочих интервалов плана без пауз, начиная с первого StartPlan. Это не календарный срок и не сумма времени параллельных исполнителей. До запуска GetSavedEstimate читает текущий прогноз без записи; первый StartPlan атомарно фиксирует его. После запуска показывается сохранённый снимок и признак устаревания при изменении источника.

До начала работы заполните признаки по схеме `agent-task-v4`. Полную схему с вложенными полями, допустимыми значениями и ограничениями возвращает `GetTrackerInfo` в `assessments.atlm.agentTaskSchema`. Её используют оба входа, `EstimatePlanTime.agentTask` и `SaveTaskAssessment.payload.context.agentTask`. Если клиент сокращает объявление инструмента, читайте сам ответ `GetTrackerInfo`. [Справочник признаков и примеры](../plugin/plan-time-tracker/skills/assess-task/references/features.md).

Сервер рассчитывает счётчики и долю операций WRITE, кодирует категории и отличает неизвестные значения от подтверждённых нулей. Интерфейс показывает названия признаков, их значения и сохранённые причины неизвестности. Для первого `StartPlan` требуется оценка со статусом `READY`. Снимок может содержать доступный прогноз или `UNAVAILABLE`, если данных для него недостаточно. [Запись оценки и проверка готовности](assessments.md).

## Расчёт

Метод `atlm/agent-v5-operations` использует преобразование `log1p(actualMs / 60000)` и сравнивает OLS, Ridge и Bayesian с исторической медианой. Ridge и Bayesian могут работать при числе признаков не меньше числа наблюдений; OLS требует полного ранга. Точечный метод выбирается отдельно от интервального. При нулевой истории прогноза нет; при одном пригодном плане возвращается `historical-median` без интервала. Начиная с двух примеров возможен экспериментальный прогноз модели.

Bayesian использует normal-inverse-gamma и прогнозное распределение Student-t с фиксированными приорами: precision 1 для стандартизованных коэффициентов и 0,000001 для свободного члена, shape 2, scale 1. `BAYESIAN_PREDICTIVE` выдаёт квантили 0,10 и 0,90. `BAYES_QUANTILE` обучает регуляризованные квантильные регрессии 0,10/0,50/0,90 на стандартизованных остатках исторического Bayesian; для каждого остатка и преобразования признаков используются только факты, доступные до начала задачи. Нужно не менее пяти таких остатков. Пересечённые квантили упорядочиваются, а границы расширяются до выбранной точки.

В `serverEstimation` находятся `pointMs`, `pointEngine` и `interval` с `status`, `lowerMs`, `upperMs`, `nominalCoverage`, `engine`, `calibrationSampleCount`, `validationStatus`, `unavailableReason`. При недоступном диапазоне границы null и указана причина. Номинальный охват 0,80 — цель, а не гарантия будущего результата. EXPERIMENTAL и HISTORICALLY_EVALUATED описывают наличие исторической проверки, а не обещание точности.

## Обучение по запросу

Worker собирает сведения о планах и измерения `PLAN_ACTIVE`. Обучение запускает агент по поручению пользователя. Ему нужны подключённый MCP с авторизацией владельца, code-mode с прямой передачей файлов, checkout проекта и Node.js 24. Схемы шести операций версии 1 и лимиты возвращают `GetTrackerInfo.assessments.atlm.registry` и `tools/list`. [Инструкция для агента](../plugin/plan-time-tracker/skills/train-model/SKILL.md).

1. `CreateTrainingSnapshot` фиксирует состояние реестра, исходную оценку, прогноз первого старта, факт, поколения источников и доказательства. Включает незавершённые и удалённые планы, исключения и источники со сбоем. При `SOURCES_PENDING` продолжайте по тому же `commandId` после указанной границы повтора.
2. Разметьте все строки. Признаки `ACTUAL` описывают выполненный объём по фактам, коду и журналу. Исходные `PLANNED` признаки остаются в снимке. Учитель объединяет связанные задачи по `groupId`, указывает причины исключений и проверяет ссылки. Подтверждённый факт допускает разметку изменившегося объёма. Неполное измерение, удаление, отсутствие завершения и терминальный сбой источника исключают строку из fit. Нулевой факт допустим, если он измерен.
3. `SaveDatasetRevision` сохраняет полный набор решений и добавляет авторитетные серверные поля. Родительская ревизия фиксирует происхождение переносимой разметки. При изменившихся поколениях проверяйте новый факт и заново обосновывайте решение. Выгрузите оригинальные байты через `GetDatasetRevision`. Сверьте `datasetDigest` с SHA-256 файла.
4. Локально запишите рецепт и выполните `train-atlm.mjs`. Изучите `evaluation.json` и `manifest.json` до решения о регистрации. При порученной регистрации передайте `registration.bundle.json` через `RegisterModelRevision`. Результат `REGISTERED` сохраняет выпуск и проверку. Указатель публикации меняется через `ActivateModelRevision`.

### Файлы и восстановление

Снимки, ревизии и отчёты выгружаются по неизменяемому ID. Повторяйте `view:'download'` до `READY` с учётом `retryAfterMs` в `MATERIALIZING`, затем читайте `view:'filePart'` по `partIndex`. Для моделей `fileKind` выбирает `BUNDLE` или `ARTIFACT`. Локальный `atlm-transfer.mjs write-part` записывает каждый кусок по позиции в `.partial`. После проверки длины и SHA-256 через `verify` опубликуйте окончательный файл. Храните в checkpoint selector, digest, размер и подтверждённые индексы.

Загрузка передаёт `file:{sha256,byteLength}` и неизменный `commandId` на `prepare`, `putPart` и `commit`. `prepare` возвращает ranges уже полученных частей. Читайте отсутствующие через `atlm-transfer.mjs read-part` и передавайте прямо из code-mode. Размер полной части 49 152 байта, лимит загрузки 16 МиБ. Для выхода локального helper, который содержит base64, используйте внутренний лимит `max_output_tokens:80000`, проверьте целостность до `putPart` и выведите наружу только метаданные. При `VALIDATING` повторяйте commit. При истечении срока частей возобновите prepare с теми же аргументами. Потерю ответа сверяйте через `GetCommandResult` и точный повтор операции. [Команды переноса и возобновления](../plugin/plan-time-tracker/skills/train-model/SKILL.md#передача-файлов).

### Рецепт локального запуска

В `recipe.json` задайте поля рецепта, подставив ID ревизии и digest полного экспорта.

```json
{
  "schemaVersion": 1,
  "recipeId": "atlm-teacher-hybrid-v1",
  "datasetRevisionId": "ID из GetDatasetRevision",
  "datasetDigest": "sha256:SHA-256 исходных байтов",
  "selection": { "mode": "ALL_ELIGIBLE" },
  "holdoutUse": "UNKNOWN",
  "holdoutUseNote": "История просмотра отложенных групп неизвестна"
}
```

`EXPLICIT` принимает `rowIds` пригодных строк и требует включить связанные группы целиком. Используйте `FIRST_REPORTED` при известной первой проверке и `REUSED_AFTER_REVIEW`, если результаты тех же групп уже видели. Рецепт сохраняет это заявление в `split` и provenance. Идентичный запуск воспроизводит результат.

```sh
cd sites/plan-time-tracker
node scripts/train-atlm.mjs --dataset /path/dataset.json --recipe /path/recipe.json --out /path/run
```

Каталог результата содержит `run.json` с версиями, digest и диагностикой, `manifest.json` с составом выборки и `evaluation.json` с режимами проверки. Код выхода `0` означает готовые `artifact.json` и `registration.bundle.json`, `2` — сохранённый отчёт о недоступном кандидате, `1` — ошибку входа или исполнения. Повтор проверяет digest выходов и переиспользует полный результат с теми же входами. Каталог публикуется атомарно. Признаки и строки сохраняются полностью, в том числе при отказе solver по пределам ресурсов. Артефакт HYBRID формата 3 хранит веса только FIT и собственный digest, а пакет регистрации закрепляет digest всей teacher-ревизии и `selectedRowIds`, `fitRowIds`, `holdoutRowIds`, `purgedRowIds`.

## Как читать оценку качества

Рецепт отделяет минимальный поздний суффикс целых групп размером от двух групп и `max(5, ceil(0.2 * selectedCount))` строк. В FIT попадают более ранние группы, чей факт готов строго до старта первой отложенной группы. Пересекающие границу группы получают `PURGED`. Если данных недостаточно для разделения, отчёт указывает недоступность holdout. Rolling replay использует только целые группы FIT с `readyAt` строго раньше старта целевой группы. Предобработка, выбор методов и калибровка опираются на эту хронологию. Для точечного выбора используются последние 20 доступных случаев и минимум пять общих сравнений. Для интервального выбора используются ошибки доступных интервалов, отдельно от выбора точки.

| Режим | Что проверяет |
| --- | --- |
| `ROLLING_GROUPED_ACTUAL` | Хронологический replay на development с восстановленными признаками фактического объёма. |
| `INTERNAL_HOLDOUT_ACTUAL` | Финальные веса на отложенных группах с признаками фактического объёма. |
| `INTERNAL_HOLDOUT_PLANNED` | Те же веса и исходные плановые признаки в случаях с подтверждённым неизменным объёмом. |
| `ISSUED_FORECASTS` | Сохранённые при первом старте прогнозы, включая недоступные, с их временем и записанной идентичностью. |

Ошибки считаются только на сопоставимых фактах. `forecastRate` и `intervalAvailabilityRate` измеряют доступность точки и интервала. `intervalCoverage` показывает долю фактов внутри доступного интервала. MAE, MedAE, смещение, ширина и interval score считаются в миллисекундах, WAPE — в процентах. Ошибка со знаком равна прогнозу минус факт. Парное сравнение использует одни и те же строки для кандидата и медианы. Широкие интервалы могут давать высокий охват, поэтому учитывайте охват вместе с шириной и interval score.

ACTUAL отражает работу после завершения. Внутренний holdout зависит от состава групп, качества разметки и истории просмотра. Маленькие когорты и повторная настройка по holdout ограничивают выводы. Фактически выданные прогнозы других ревизий показывают качество этих выдач. Проспективная оценка кандидата появляется, когда его ревизия уже активирована и выдала прогнозы для завершённых сопоставимых задач.

## Активация и история

Сравните `activeModelRevisionId` и `servingModelRevisionId` в `ListModelRevisions`. Первый хранит назначение для CAS, второй показывает модель, доступную для новых прогнозов. Для активации передайте `modelRevisionId`, `expectedActiveModelRevisionId`, `expectedActivationVersion`, новый `commandId` и причину. Ревизия проходит допуск при доступном плановом holdout, как минимум пяти сопоставимых парах из двух групп и MAE кандидата не выше MAE медианы на этих же парах. Экспериментальную ревизию можно активировать с явным `acceptExperimental:true` по поручению пользователя. Неверный артефакт или изменившийся источник блокируют активацию независимо от подтверждения.

Изменение поколения любого использованного источника, включая HOLDOUT и PURGED, сразу делает выпуск непригодным для новых прогнозов. Сохранённый прогноз начатого плана остаётся прежним. Новый план вне выборки и новая ревизия разметки сами по себе не меняют пригодность модели. Для отката выберите прежнюю пригодную ревизию и повторите `ActivateModelRevision` с текущими CAS-значениями. Причина и результат останутся в истории.

Исторические ревизии сохраняют исходные байты артефакта, отчёт и известную историю публикаций. Например, `atlm-11-r2` хранит прежний результат `REJECTED/INSUFFICIENT_INCUMBENT_CASES` рядом с фактом публикации. Неизвестные даты и источники остаются `null`. Архив можно выгрузить для аудита. При `HISTORICAL_PROVENANCE_INCOMPLETE` подготовьте новый нативный снимок с проверенной разметкой для обучения.

Если после сброса истории исходный снимок отсутствует, `GetSavedEstimate` возвращает `HISTORY_RESET`. Возобновление начатого плана по-прежнему доступно.

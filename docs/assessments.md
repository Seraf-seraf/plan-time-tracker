# Оценки и фактическое время

SaveTaskAssessment сохраняет неизменяемую оценку плана или этапа. Метод, шкалу, сложность, допущения и способ решения задаёт агент. Для первой записи используется expectedVersion=0; для ревизии нужны текущая версия серии и причина. Команды защищены квитанциями и CAS.

Перед анализом вызовите GetTaskAssessment без assessmentId и сохраните `currentRequirementsDigest` как `expectedRequirementsDigest`. При изменении требований сервер отклоняет запись; перечитайте контекст и пересмотрите оценку. GetTaskAssessment с assessmentId возвращает ревизию и признак needsRevision.

Для прогноза до первого запуска сохраните оценку плана без `stepId`. Передайте `context.agentTask` по `GetTrackerInfo.assessments.atlm.agentTaskSchema` и `predictionRequest:{method:"ATLM",methodVersion:1}`. Сервер рассчитывает `serverEstimation`. Поля `method`, `complexity` и `forecast` относятся к оценке агента, поэтому при запросе только серверного прогноза передайте `forecast.status="UNKNOWN"` с пустыми границами. Размер оценки вместе с серверным прогнозом ограничен 65 536 байтами UTF-8 и глубиной JSON 12. [Справочник признаков и пример запроса](../plugin/plan-time-tracker/skills/assess-task/references/features.md#запрос-сохранения-оценки).

`GetTimeHistory` читает выбранные `targets` и период `from`, `to`, `timeZone`. `PLAN_ACTIVE`, `CALENDAR` и `PAUSED` измеряются в миллисекундах для родительского плана, в том числе при запросе по этапу. Общий итог объединяет интервалы выбранных планов. Готовность отражает текущее состояние. Период ограничивает фактическое время, а ревизии читаются по `asOf` и `throughSequence`. Для следующей страницы сохраните эти два значения, а `nextAfterSequence` передайте как `afterSequence`. [Контракт времени этапов](plan-documents.md#записанное-время-этапов).

Перед первым `StartPlan` прочитайте `assessmentReadiness` из `GetSavedEstimate`. При `READY` можно начинать работу, даже если `serverEstimation.status` равен `UNAVAILABLE`. Если оценки ещё нет, создайте серию. Если оценка неполная или недействительная, используйте `missingPaths` и `invalidPaths` для исправления. При `STALE` перечитайте требования, при `OUTDATED` заполните признаки текущей схемы. Сохраните ревизию и отправьте новую команду запуска. Для точного повтора с тем же `commandId` сервер вернёт исходную квитанцию.
